# 🛡️ Authority Vault - Access Control System

This project uses a centralized, source-of-truth ACL (Access Control List) system to manage security across the UI menu, protected routes, and administrative API synchronizations.

## 📂 Key Files
- `src/app/acl.config.ts`: **The only file you should edit.** Contains role definitions and module mappings.
- `src/app/store/app.store.ts`: Derived state and API-level synchronization guards.
- `src/app/app.routes.ts`: Router guards synchronized with the ACL config.

## ⚙️ How it Works

### 1. Defining Roles
Role names are defined in the `ACL_ROLES` object. Use standard Keycloak role names here.
```typescript
export const ACL_ROLES = {
  VAULT_ADMIN: 'vault_admin',
  SALES: 'sales_team'
};
```

### 2. Mapping Modules
The `MODULE_PERMISSIONS` object determines which roles can see and access specific areas of the application.
```typescript
Identities: [ACL_ROLES.VAULT_ADMIN],
Analytics: [ACL_ROLES.VAULT_ADMIN, ACL_ROLES.SALES]
```

### 3. Registry Sync Protection
To prevent unauthorized API traffic (and 403 errors), the `REGISTRY_SYNC_ROLES` array determines which users trigger the `users` and `roles` data handshake.

## 🚀 Adding a New Module
1. Create your component and route.
2. In `app.routes.ts`, set `data: { roles: MODULE_PERMISSIONS['YourModuleName'] }`.
3. In `app.html`, wrap your nav link in `@if (checkModuleAccess('YourModuleName'))`.
4. Define the permissions in `acl.config.ts`.
